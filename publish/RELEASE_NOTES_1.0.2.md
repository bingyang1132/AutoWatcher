本 Mod 的清单里求解器写的是**最低版本** `0.32.0`，不是精确版本。低于它、或者缺了某个登记入口，
本 Mod 会干净地拒绝加载并在日志里写明缺什么。

会按新规则算，遇到那个特定情形会偏乐观。

## 这一版改了什么

### 跟进观者 `0.9.28`

**通晓万物**。0.9.28 起，选到一张**被自己的条件挡住**的牌时，原版直接把它消耗掉，不再打两次。
最典型的是华丽终章：它要抽牌堆清空才打得出，抽牌堆里还有别的牌时就属于这种情形。
以前求解器会把一次完整的双倍出牌算进路线，实机只是把牌消耗掉——这是会**静默算错**的那一类，
不是打红字提示的那一类。

**预见回收经纬**。0.9.28 修了一个 mod 侧的 bug：0.9.27 的代码认的卡牌 id 对不上，实机压根没把
弃牌堆里的经纬收回来。我们的镜像一直是按「该回收」算的，所以在 0.9.27 上偏乐观；从 0.9.28 起
两边对上了。

0.9.27 → 0.9.28 一共 +927 / −25 行，除上面两处以外全是审判的新特效、音效和卡面开关。
审判自己的斩杀判据一个字没动。逐条比对见 [docs/VERIFICATION.md](../docs/VERIFICATION.md)。

### 跟进求解器 `0.34.8`

重新编译并核过全部登记入口与补丁目标。0.34.8 顺带修了临时力量／敏捷／集中的施加顺序，
和下面「阳」那条是同一族问题的另一半。

### 修好的算错

**阳**。这个遗物给的临时敏捷原来只加了记账层，没有配上等量的常驻敏捷；回合结束时却照着记账层
把真敏捷扣掉。结果不是少算而是**算反**——本回合起甲少算，下一回合开局凭空多出一个负敏捷。
实机表现是永世沙漏战每回合都计划外重算。

**净化不肯烧起手牌**。观者真正的引擎牌（全知、内心宁静、许愿）牌面上没有伤害/格挡/抽牌数值，
求解器的通用估值一律给 0 分，于是净化永远先烧引擎、留下一堆打击。这一版给观者的起手打击和
防御声明了负偏置，「烧掉它」这条分支才排得到「一张都不烧」前面。

**真言的战略估值**。真言原来落进求解器的默认兜底，被记成「成长潜力」，于是「先祈祷推到 10、
进神格、拿多出来的能量打伤害」这条线在动作分类里完全不产生**资源**信号。现在按
「离下一次兑现还差多少」登记成资源刻度，一次兑现封顶 3 费。

**勤学精进和许愿的金币各占一份成长额度**。这两处收益原来只记「这条线路带走了多少局外价值」，
那笔账永远换不到血。现在它们出现在求解器的成长策略侧栏里，可以各自填一个「每次收益允许的
额外战损」。

## 已知不准的地方

**1 处**效果没有建模：画符（`WATCHER_DRAW_TALISMAN`）的批量临时附魔。它**不会静默算错**——
求解器会在路线上打红字标明「这里有未镜像的效果」。完整清单在
[docs/VERIFICATION.md](../docs/VERIFICATION.md)。

**新增一条提醒（不是本 Mod 的 bug，但和本 Mod 有关）。** 在求解器的成长策略侧栏里给
勤学精进或许愿的金币填了非零额度之后，求解器会**关掉「打到可接受战损就提早收手」那条捷径**，
于是每一场战斗都会把深化搜索的时间预算跑满。求解器这么做有它的道理——多兑现一次成长收益
本来就是更好的路线，零战损不代表到顶了——但它不检查「还兑不兑得出来」，所以哪怕本场只有一张
勤学精进、而且已经斩杀兑现过了，它照样会接着搜。

如果你觉得每回合等太久，把这两个额度填回 0 即可。

  立刻挂在「首个选牌是 `GRAND_FINALE`，预期 `WATCHER_STRIKE_P`」——求解器确实会去选那张
  它以为能打出 120 点群体伤害的牌。恢复后重新通过。

  `0.111.0`）。0 失败、0 未运行。求解器和观者两样同时换版之后的第一次全量。
