# Release 说明模板

每次发 GitHub release 都照这个填。两件事必须写清：**对标哪一个求解器版本**，和**这一版有什么
已知不准的地方**。少了前者用户会装错对，少了后者他们会把已知缺口当成 bug。

标题用 `v<版本> · 对标求解器 <版本>`，例如 `v1.0.0 · 对标求解器 0.32.0`。

---

## 对标的版本

| | 版本 | 从哪拿 |
|---|---|---|
| 自动战斗求解器 | `<求解器版本>` | `<那一版的下载链接>` |
| 观者（Boninall） | `<观者版本>` | 创意工坊 |
| 游戏 | `<游戏版本>` | — |

本 Mod 的清单里求解器写的是**最低版本** `<min_version>`，不是精确版本。低于它、或者缺了某个
登记入口，本 Mod 会干净地拒绝加载并在日志里写明缺什么。

## 已知不准的地方

`<数量>` 处效果没有建模。它们**不会静默算错** —— 求解器会在路线上打红字标明「这里有未镜像的
效果」。完整清单在 [docs/VERIFICATION.md](../docs/VERIFICATION.md)。

## 报 Bug

求解器自带问题包导出。导出后开 issue 附上它，说明你装的是工坊版还是 GitHub 版。
带上问题包基本都能定位；只有文字描述通常不够。
